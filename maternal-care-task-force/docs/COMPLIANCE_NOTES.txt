MCTF MEMBER SITE — COMPLIANCE NOTES
Prepared for the Task Force co-chairs and county health department privacy officers
2026-09-03

1. PHI TOUCHED AND WHERE IT FLOWS
   Intended: NONE. The system stores governance content, public program
   listings, aggregate county statistics, professional member identities,
   and de-identified barrier categories.
   Personal data (not PHI) that is stored: member names, organizations,
   roles; member email/phone only with opt-in; reporter email on form rows
   (verified by Google, never served to the site).
   Flow: Google Forms -> content Sheet (admin-owned) -> Apps Script web app
   (execute as admin) -> browser -> Google Sites iframe. No third party
   receives any data. No analytics, tag manager, or pixel is included.

2. CONTROLS APPLIED
   - Hosting: Performance Health Group Google Workspace (HIPAA BAA
     accepted) during development and deployment; owner
     admin@performancehealthgroup.org. Hosting is a technical role only and
     confers no editorial authority: content decisions belong to the
     co-chairs, and the neutrality rule below binds the host exactly as it
     binds any other member.
   - Web app access: "Anyone" (no sign-in). The deployment URL is public;
     the Published gate is the only content control.
   - Authorization: web app is read-only and anonymous. Every entry point
     runs authorizeRead_ then an audit write, then work (Api.gs). Admin
     functions run requireAdmin_ (Auth.gs) against a Script Properties
     allowlist that defaults to the deploying account.
   - Publication gate: only rows with Published = TRUE leave the sheet.
     Form free-text is served only after a co-chair marks it Published.
   - Contact consent gate: member Email/Phone served only if ShareContact.
   - Data access: all Sheets I/O in DataAccess.gs via openById under the
     service identity; never getActiveSpreadsheet.
   - Audit: separate spreadsheet, separate folder, six-year retention;
     entries hold actor, role, action, resource, outcome, session; no content.
     Bootstrap ordering: the first runSetup performs its admin check before
     it creates the audit spreadsheet, so that one SETUP entry has nowhere
     to write. writeAudit_ buffers such an entry and flushPendingAudit_
     replays it as soon as the spreadsheet exists, carrying its original
     timestamp and a justification marking it a deferred write. Projects
     provisioned before this fix log AUDIT_WRITE_FAILED instead and can
     close the gap with backfillSetupAudit() in Setup.gs, which writes the
     row explicitly labelled BACKFILLED. No audit row is ever edited or
     deleted; corrections are additional rows.
   - Output encoding: all sheet text is HTML-escaped client-side; links are
     rendered only for http(s) URLs.
   - No secrets in code; IDs in Script Properties.
   - Barrier form: month-only date, closed-choice categories, 500-char text,
     explicit prohibition of identifiers on the form and on the site.

4. REGULATORY REQUIREMENTS IMPLICATED
   - HIPAA Privacy Rule minimum necessary; de-identification standard
     (164.514) as the bar for anything narrative on the site.
   - HIPAA Security Rule audit controls and six-year documentation
     retention (164.312(b), 164.316(b)(2)(i)) applied by policy even though
     no ePHI is expected.
   - Maryland PIPA: member emails/phones are personal information; opt-in
     and minimal storage applied.
   - Neutrality: the site is a Task Force tool, not a marketing channel for
     any member organization. Member listings state professional role only;
     no member organization's services are described, ranked, or promoted;
     resource rows are added only through the same review as every other
     row. Task Force participation is separate from any member's business
     interests, and the site must not be used to advance them.

5. RESIDUAL RISK
   - Admin error publishing identifying text. Mitigation: review columns on
     form tabs; periodic spot-check by Privacy Officer; footer reminder.
   - The web app URL is public by design ("Anyone"). Mitigation: content is
     public-safe by design; co-chair review before Published = TRUE; rotate
     the deployment if the URL is misused.
   - PHG hosts the system while also being a member organization.
     Mitigation: neutrality rule, co-chair content approval, audit log, and
     a documented handoff path to a county account.
   - Sheets has no row-level security; anyone with sheet Editor access sees
     reporter emails. Mitigation: Editor access limited to named admins.
   - An admin with Editor access to the audit spreadsheet could alter it;
     Sheets cannot enforce append-only. Mitigation: audit file kept in a
     folder no portal user can reach, Editor access limited to named
     admins, and Drive file-level revision history retained.

6. PRE-LAUNCH AUDIT
   A seven-lens adversarial audit was run on 2026-09-04 before deployment.
   26 verified findings, including 5 blockers — one of which (a published
   action item that could re-identify a single patient) would have been a
   reportable disclosure had the site been live. All blockers and all high
   findings were corrected in version 1.1.0. Full record and remaining open
   work: docs/AUDIT_2026-09-04.txt.

   The audit is the reason for three standing rules now in the code:
     - readPublished_ fails CLOSED, so a damaged Published header withholds a
       tab rather than publishing it.
     - Every audit field is neutralized against formula injection, because an
       anonymous URL parameter reaches the log.
     - Only allowlisted Config keys are served; the Config tab cannot be gated.

7. BARRIER REPORT VISIBILITY (owner decision, 2026-09-04)
   Every barrier report is now readable in full by every visitor as soon as
   it is submitted, replacing the co-chair review gate that previously held
   free text back until Published = TRUE. Reports remain listed with their
   review state so a reader can see which have been checked.

   // COMPLIANCE ASSUMPTION: Members will follow the form's instruction not
   //   to enter identifying details, so unreviewed free text is safe to
   //   publish immediately.
   // BASIS: Owner decision, 2026-09-04. The Task Force needs to see what is
   //   being reported to act on it; a review queue that delays publication

   //   reporter's slip becomes world-readable with no step in between and no

   // MITIGATIONS IN CODE: reporter email is never served; scrubIdentifiers_
